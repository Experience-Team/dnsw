Using a token

Always use the role, never a raw value or a brand's palette token:

/* Yes */
.my-card { background: var(--c-surface); color: var(--c-ink); border: var(--bw-1) solid var(--c-line); }

/* No: breaks in every other brand */
.my-card { background: #fff; color: #1a1a1a; }
.my-card { background: var(--tth-color-chalk); }

Two token sets today

The page wireframes use --color-*; the prototypes use the fuller --c-* roles. New work uses --c-*. Moving the page wireframes onto --c-* is on the roadmap.

Adding a live example

  1. Copy the markup from the component's render code into examples.js under a new key, and name the source in a comment.
  2. Put <div data-ds="example" data-ex="your-key" data-title="..."></div> in the page.
  3. The example renders in frame.html with shared.css and the theme files, in the brand picked above it.

Running it locally

The site uses clean addresses (/design-system/styles/colour), which Vercel serves through a rewrite in vercel.json. Locally, use vercel dev, or any static server that falls back to public/design-system/index.html for addresses under /design-system.
