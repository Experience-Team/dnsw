Reading a token

Every token has a name, a value and a use. Names say what a value is for, not what it looks like: --c-ink-2 is secondary text, whatever colour a brand makes it. When a value comes from another token, the chain is shown under it, for example --c-accent via --tth-surface-brand → --tth-color-orange.

Use the Brand switch above any token table or example to see the same roles in another brand. Values a brand sets itself are marked Brand; the rest come from the Wireframe base.

Designing with the system

  1. Start from the roles. Pick colours from the role swatches, never from the brand's palette directly, so the design works in every brand.
  2. Use the type scale and the 4px spacing scale. If a size is missing, ask before adding one; a new value is a change to the system.
  3. Check the component's page for its states and behaviour before drawing a new variant. Most "new" components are an existing one in a new place.
  4. Check the interaction rules: they set how sheets, toasts and selection behave, and every prototype is checked against them.

Handing over

  • Name the components you used, using the names in the inventory.
  • Call out anything new: a value, a variant or a component. It goes through contributing.
  • Say which fields come from the product data contract and what each module shows when one is missing.
