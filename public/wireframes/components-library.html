Carousel & tab bar Resolved

.carousel-bleed extends a horizontally-scrolling .carousel to the viewport edge. .tab-bar is a simple active/inactive button row. Every carousel on the site now bleeds, and .carousel-nav is always a direct .section-header child with no wrapper — .section-header's own display:flex; justify-content:space-between; already positions it correctly.

home-nsw.html's 3 carousels (experiences, driving itineraries, top events) were the only ones not wrapped in .carousel-bleed — they stayed inside .container instead of bleeding to the viewport edge. Now fixed to match every other page, including re-wrapping each carousel's trailing "view all"/CTA link back in its own .container so it stays centred below the full-bleed carousel.

home.html, accommodation.html and events.html each wrapped .carousel-nav in a redundant inline-styled <div style="display:flex;align-items:center;gap:.75rem;"> — unnecessary since .section-header already lays out its two children the same way. All 3 now place .carousel-nav directly, matching home-nsw.html's pattern.

western-sydney.html's 4 carousels are a deliberately different case, not folded into the above: their .section-header has no nav at all — .carousel-nav instead sits below the carousel, paired with a "Browse more…" link in a space-between row. That's a distinct list-preview-with-CTA pattern, not a placement variant of the same control, so it's left as-is rather than forced into the header.

Filter & date modals Resolved

One .filters-modal shell is reused for 5 structurally distinct pieces of content — that's intentional (a shared shell for a nested accordion, a flat property/star-rating list, raw price inputs, a date picker, and standalone single-purpose modals). What wasn't intentional: the footer button verbs had drifted to 5 different wordings ("See results" / "Done" / "Clear" / "Apply" / "Clear all") with no shared convention. Now there are exactly two, chosen by what the button does: "Clear all" for every clear/reset button (was "Clear" on 2 of 7), and "See results" for the 4 modals that directly gate the page's main visible listing (accommodation's "Filter accommodation" and "Price per night" modals, events' "Filters" and "When" modals — was "Apply"/"Done" on 2 of these), vs. "Done" for the 3 standalone sub-modals (Location, Category, Accessibility) that just confirm a selection within V2/V3's larger live-updating filter system rather than triggering the filtering action themselves.

Map modules Resolved

Four map implementations, kept as four — each serves a genuinely different purpose (a static custom-drawn regional map, a list/map toggle for a results grid, an interactive neighbourhood-picker, and a schematic distance diagram), so this isn't a case of picking one canonical shape. The only real bug found was cosmetic drift between the two .map-panel Google Maps embeds: events.html's iframe carried an inline border-radius:.5rem and accommodation.html's carried display:block instead — both redundant, since #map-content-row.map-active .map-panel iframe in shared.css already sets width/height/display, and the .map-panel container itself already clips to a rounded corner via overflow:hidden. Both iframes are now down to the one style they actually need, border:0. The .area-map markup, data and JS being duplicated verbatim between western-sydney V2 and V3 is intentional reuse (confirmed byte-identical, no drift) rather than a bug — there's no shared-include mechanism in this static wireframe setup to de-duplicate it further.

Orphaned components Resolved

components/card.html defined a generic .card partial (.card-img, .placeholder-img, .card-body, .card-title, .card-text) that was never referenced by any of the 8 pages, and its class names had no matching rules in shared.css — it rendered unstyled if ever included. The file has been deleted rather than reconciled, since every real content-card need is already covered by one of the five real card variants.
