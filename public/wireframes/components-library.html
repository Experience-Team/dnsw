Carousel & tab bar

.carousel-bleed extends a horizontally-scrolling .carousel to the viewport edge. .tab-bar is a simple active/inactive button row.

Inconsistency — home-nsw.html's carousels (experiences, driving itineraries, top events) are NOT wrapped in .carousel-bleed — they stay inside .container, so they don't bleed to the viewport edge like every other page's carousels.
Inconsistency — .carousel-nav (‹ ›) placement varies: beside the title in an undocumented inline-styled wrapper (home, accommodation), a direct .section-header child (home-nsw, events), or below the carousel next to a CTA button (western-sydney.html) — three placements for one control.

Filter bars — three parallel systems

events.html ships three entirely different filter-bar interaction patterns, switchable live via a dev-only .variant-switcher (see "Dev-only tools" below). Other pages each independently picked a reduced subset of V1 — there is no single converged "final" pattern in use sitewide.

Not yet decided. Because events.html still ships all three as an A/B comparison, and accommodation.html / western-sydney-v2/v3.html each only adopted V1 (in a reduced form with fewer action buttons), the site currently has no consistent filter UI. This is the single highest-value inconsistency to resolve.
